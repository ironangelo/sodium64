### E2a batch 7 — root cause found: new helper occupies `dma_wait` return delay slot

This is an analytical extrapolation, not a performance measurement, but it is sufficient to forbid treating the E3a scalar staging loop as the production full-frame implementation by default. If semantics close, the next production-oriented compositor batch must seek materially coarser streaming/vector/band ownership and then measure it; E3a exists to prove dataflow/semantics only.
- **STATIC CONVERSION CHECK / E3a support:** source-level `ppu.S:update_dpal` at full brightness maps SNES BGR555 `(R bits0..4,G5..9,B10..14)` exactly to N64 RGBA5551 `R<<11 | G<<6 | B<<1 | 1`; therefore `RGBA5551 >> 1` is three contiguous 5-bit fields `(R high,G middle,B low)`. The pinned ares full-add identity is field-order invariant because it isolates the same 5-bit boundaries. An independent host check over **343 structured colors** with channels `{0,1,2,15,16,30,31}` = **117,649 color pairs** found zero mismatches between packed ADD on shifted N64 words and explicit per-channel saturating ADD followed by N64 repack. This is static/algebraic support only; E3a still needs dynamic rendered evidence.
